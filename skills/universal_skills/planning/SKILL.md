# Planning

## Purpose
Create clear, practical plans for tasks and projects before implementation.

## When to use
Use when a task involves multiple steps, architectural decisions, dependencies, or meaningful trade-offs.

## Procedure
1. Identify the goal and success criteria.
2. Identify constraints, assumptions, and dependencies.
3. Break the work into small, ordered steps.
4. Identify risks and alternatives.
5. Choose the simplest viable approach.
6. Define verification criteria.

## Rules
- Do not over-plan trivial tasks.
- Do not invent missing requirements; state assumptions.
- Prefer incremental, reversible changes.
- Keep plans aligned with the existing project architecture.
