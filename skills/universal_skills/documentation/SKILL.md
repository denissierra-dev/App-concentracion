# Documentation

## Purpose
Create and maintain accurate documentation that helps users and developers understand the project.

## When to use
Use when documenting APIs, architecture, setup, workflows, decisions, features, or non-obvious behavior.

## Procedure
1. Identify the intended audience.
2. Explain purpose and prerequisites.
3. Provide concrete usage examples when useful.
4. Document important constraints and failure modes.
5. Keep documentation synchronized with the implementation.

## Rules
- Do not document behavior that does not exist.
- Prefer concise explanations and practical examples.
- Explain why for non-obvious architectural decisions.
- Update affected documentation when behavior changes.
