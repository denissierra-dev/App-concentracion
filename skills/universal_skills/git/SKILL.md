# Git

## Purpose
Use Git safely and consistently for version control.

## When to use
Use when creating commits, branches, merges, rebases, resolving conflicts, or inspecting project history.

## Procedure
1. Inspect the current repository state.
2. Understand the intended change.
3. Keep changes focused.
4. Review the diff before committing.
5. Write clear commit messages.
6. Verify the resulting repository state.

## Rules
- Never discard user changes without explicit authorization.
- Do not commit secrets, credentials, or generated sensitive files.
- Avoid mixing unrelated changes in one commit.
- Prefer reversible operations when possible.
