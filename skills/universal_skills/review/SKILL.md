# Review

## Purpose
Evaluate changes for correctness, maintainability, security, performance, and consistency.

## When to use
Use when reviewing code, designs, architecture, pull requests, or proposed changes.

## Procedure
1. Understand the intended behavior.
2. Check correctness and edge cases.
3. Check architecture and maintainability.
4. Check error handling and security.
5. Check performance where relevant.
6. Check tests and documentation.
7. Prioritize findings by severity and confidence.

## Rules
- Focus on actionable findings.
- Do not criticize harmless stylistic differences without a project convention.
- Separate definite problems from suggestions.
- Explain the impact of important findings.
